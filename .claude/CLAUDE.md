## 📌 프로젝트 개요

**서비스 주제**: 사용자 맞춤형 환경 정보(날씨·대기질 등)를 개인화된 방식으로 시각화하는 모바일 앱

---

## 🗺️ 핵심 시나리오 (3개 화면)

### 1. 온보딩 (로그인 후 최초 진입)

- **Step 1** — 민감군 선택 (일반 / 천식·호흡기 / 영유아 동반 / 노인, 복수 선택 가능)
- **Step 2** — 주요 활동 시간대 등록 (출근·퇴근·등교 등, 최대 5개, 개별 알림 토글)
- **Step 3** — 관심 장소 등록 (최대 5개, 장소명 + 좌표 + 아이콘)
- **Step 4** — 체감 온도 성향 측정 (0·10·20·30°C 기준 5지선다)
- 완료 후 설정 요약 화면 → 메인 페이지 이동
- 재방문 시 온보딩 스킵, 마지막 설정 기반으로 바로 메인 진입

### 2. 메인 페이지 (지도 히트맵)

- **히트맵 레이어**: 미세먼지(PM2.5), 초미세먼지(PM10), 기온, 체감온도, 자외선 지수, 강수 확률
- **데이터 출처**: 에어코리아 API, 기상청 API
- **지도**: Mapbox GL JS 기반, 현재 위치 자동 중심, 관심 장소 핀 표시
- **필터 UI**: `[대기질] [기온/체감] [자외선] [강수] [복합 위험도]` 탭, 단일/복합 선택
- **시간 슬라이더**: 현재 시각 기준 ±12시간 예보 데이터 확인
- **상단 요약 카드**: 핵심 지표 3개 + 다음 활동 시간대까지 남은 시간 + 민감군 맞춤 경고 배너

### 3. AI 질문 페이지

- **자주 묻는 질문 버튼 UI** (민감군·시간대·장소 기반 동적 생성)
  - 공통: "지금 외출해도 괜찮아?", "오늘 나한테 덥거나 추울까?", "오늘 운동하기 좋은 날이야?", "미세먼지 언제 나아져?"
  - 천식·호흡기 추가: "오늘 마스크 꼭 써야 해?", "환기해도 될까?"
  - 영유아 동반 추가: "아이 데리고 공원 나가도 돼?", "유아차 나들이 가능?"
  - 노인 추가: "오늘 열사병 위험 있어?", "한파 주의 필요해?"
  - 등록된 활동 시간대 2시간 이내 시 강조 버튼 자동 노출
- **직접 프롬프팅**: 자유 텍스트 입력, 온보딩 정보를 컨텍스트로 자동 주입
- **AI**: Claude API 사용

## 🧬 폴더 구조 — FSD 아키텍처 (필수)

> **모든 신규 기능은 반드시 이 구조를 따른다.** 단일 파일로 풀어 두지 말고, 아래 레이어로 책임을 분리한다. Claude는 새 feature를 만들거나 기존 feature를 리팩토링할 때 이 규칙을 우선 적용해야 한다.

```
src/features/{feature(domain)}/
├── components/    # presentational only. props 입출력만, 외부 상태 의존 금지
├── containers/    # hooks·data를 wiring해서 components를 조립
├── hooks/         # 상태/사이드이펙트 로직. useXxx 형태로 export
├── constants/     # 도메인 상수·타입. 폴더 권장(파일 1개여도 폴더로 유지)
└── ...            # 필요 시 api/, utils/ 등 추가
```

### 레이어 책임 경계
- `components/`: 순수 UI. 내부 `useState`는 입력 폼 드래프트 같이 **그 컴포넌트 안에서만 의미 있는** 상태에 한정.
- `containers/`: hook을 호출해 상태를 받고, `components/`에 props로 내려준다. JSX는 조립용으로만.
- `hooks/`: 비즈니스 상태·로직. 컴포넌트와 무관하게 단위 테스트 가능한 형태.
- `constants/`: 도메인별 파일로 쪼개고 `index.ts`에서 re-export. 도메인 타입(`type XxxEntry`)도 여기에 같이 둔다.

### feature 간 의존
- 한 feature가 다른 feature를 직접 import하지 않는다 (`features/a` → `features/b` 금지). 공유가 필요하면 `shared/`로 올린다.

## 📄 코드 컨벤션

### TypeScript

| 항목          | 규칙                                                           |
| ------------- | -------------------------------------------------------------- |
| 타입 선언     | `type` 만 사용 (`interface` 사용 금지)                         |
| 컴포넌트 선언 | `function Component() {}` 형태 사용 (`const` 화살표 함수 금지) |
| export        | `export` 만 사용 (`export default` 사용 금지)                  |

### 네이밍 컨벤션

| 대상              | 형식         | 예시                                |
| ----------------- | ------------ | ----------------------------------- |
| 컴포넌트명 / 훅명 | `PascalCase` | `HeatmapLayer`, `useWeatherData`    |
| 상수              | `UPPERCASE`  | `MAX_LOCATIONS`                     |
| 일반 변수         | `camelCase`  | `currentTemp`                       |
| 파일명 / 폴더명   | `snake-case` | `heatmap-layer.tsx`, `air-quality/` |
| 타입명            | `PascalCase` | `export type TemperatureType`       |

```

```

### 커밋 컨벤션 (Gitmoji)

| 이모지 | prefix     | 설명                                 |
| ------ | ---------- | ------------------------------------ |
| ✨     | `feat`     | 새로운 기능 구현                     |
| 🐛     | `fix`      | 코드 수정, 버그/오류 해결            |
| 📦     | `chore`    | 동작에 영향 없는 변경 (주석 추가 등) |
| 📝     | `docs`     | README 등 문서 수정                  |
| 🚀     | `deploy`   | 배포 관련                            |
| 💄     | `style`    | 디자인 관련                          |
| ♻️     | `refactor` | 전면 수정, 코드 리팩토링             |
| ✅     | `test`     | 테스트 추가/수정                     |

### Issue & PR 제목 형식

```
[칸반 태그 UPPERCASE] 구현할 내용
```
